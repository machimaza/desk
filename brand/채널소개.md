# 채널 소개글 — 6개 채널

핸들·주소의 출처는 `channels.json` 입니다. 여기 적힌 문구만 손으로 붙여넣습니다.
**자동 발행하지 않습니다** — 네이버·티스토리는 자동화가 약관 위반이고,
인스타·쓰레드는 소개글을 API 로 바꿀 수 없습니다.

---

## 0. 무엇이 들어가야 하나 — 여덟 가지

소개글은 "우리가 누구인가"가 아니라 **"이 사람 말을 믿어도 되나"** 에 답하는 자리입니다.
그래서 성격 소개가 아니라 **검증 방식**을 씁니다.

| # | 넣을 것 | 왜 |
|---|---|---|
| 1 | **한 줄 정체성** — 마침 필요한 정보를, 알맞게 | 3초 안에 이탈 여부가 갈립니다 |
| 2 | **두 축** — 언제까지인지 · 내 구간에서 얼마인지 | 우리가 다른 곳과 다른 지점이 정확히 이 둘입니다 |
| 3 | **다루는 범위 3개** — 건강보험 · 세금 · 지원금 | 넷을 넘으면 아무것도 기억되지 않습니다 |
| 4 | **검증 방식** — 정부·공공기관 원문 확인 | E-E-A-T 신호 중 가장 싸고 가장 강한 것 |
| 5 | **기준연도 표기** | 이 니치의 상위 노출 글 대부분이 작년 숫자를 씁니다. 그걸 안 한다고 말하는 게 차별점입니다 |
| 6 | **갱신 약속** — 개정되면 갱신 | 한 번 쓰고 방치하는 곳과 갈립니다 |
| 7 | **고지** — 정보 제공용, 최종 확인은 해당 기관 | YMYL 영역입니다. 신뢰를 깎지 않고 오히려 올립니다 |
| 8 | **행동 하나** — 링크 또는 저장 | 두 개 이상 요구하면 아무것도 안 합니다 |

### 넣지 말 것

| 안 넣는 것 | 왜 |
|---|---|
| 자격·직함 (세무사·노무사 등) | **사실이 아니면 사칭입니다.** 우리 신뢰는 자격이 아니라 원문 대조에서 나옵니다 |
| "무조건 받는 돈" · "모르면 손해" | 과장·불안 조성. `lint_style.py` 가 본문에서 막는 표현을 소개글에 쓰면 앞뒤가 안 맞습니다 |
| 종목·수익률 이야기 | 금융소비자보호법 제22조 주체 요건 위험 (2장) |
| "구독과 좋아요" | 지면을 먹고 신뢰를 깎습니다. 소개글의 일이 아닙니다 |
| 이모지 도배 | 톤과 어긋납니다. 구분자는 `·` 와 `|` 로 충분합니다 |
| 채널 6개 전부 나열 | 소개글마다 6줄이 링크가 됩니다. **블로그 하나만** 가리키고 나머지는 홈페이지가 모읍니다 |

### 어디를 가리키나

**허브는 `machimaza.github.io/desk/` 하나입니다.** 영상·소셜은 전부 여기로 보내고,
허브가 블로그 두 곳과 나머지 채널을 모읍니다. 채널마다 링크를 다르게 두면
어디가 본진인지 아무도 모르게 됩니다.

> **주소가 아쉽습니다.** `/desk/` 는 저장소 이름이 그대로 드러난 주소라
> 소개글에 적으면 임시로 만든 페이지처럼 읽힙니다. 두 가지 선택지가 있습니다 —
> ① `machimaza.github.io` 라는 이름의 저장소를 따로 만들어 허브만 옮기면
> 주소가 `machimaza.github.io` 로 짧아집니다(무료).
> ② 도메인을 사서 붙입니다(연 1~2만원대).
> **바꿀 거면 소개글을 여섯 곳에 붙이기 전에 바꾸는 편이 낫습니다.**
