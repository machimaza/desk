# 다른 프로젝트로 옮기기 — 깃 자동 커밋 · 유튜브 자동 업로드

다른 코워크(또는 다른 세션)에서 같은 것을 하려고 할 때 읽는 문서입니다.
**여기 적힌 함정은 전부 실제로 밟아본 것들입니다.**

| 하고 싶은 것 | 필요한 것 | 준비 시간 |
|---|---|---|
| 코드·문서를 깃에 자동 커밋 | claude.ai **GitHub 커넥터** 하나 | 1분 (사람이 클릭) |
| 영상을 유튜브에 자동 업로드 | 구글 OAuth 3종 + GitHub Actions Secrets | 30분 (한 번만) |

둘은 **서로 독립**입니다. 하나만 해도 됩니다.

---

## 1. 깃 자동 커밋

### 준비 — 사람이 하는 일은 이것뿐입니다

claude.ai → 설정 → 커넥터 → **GitHub 연결**. OAuth 로 붙습니다.
붙고 나면 세션에 `mcp__github_connect__*` 도구가 생깁니다.

### 컨테이너의 `git push` 는 안 됩니다

이게 첫 번째 함정입니다. 세션 안에서 그냥 밀면 이렇게 막힙니다.

```
remote: access denied by the git proxy: <repo> is not in this session's
        authorized repository set, so the proxy will not inject a credential
fatal: ... error: 403
```

컨테이너는 깃 프록시를 거치는데 저장소가 허용 목록에 없으면 **자격증명을 아예 안 넣어줍니다.**
`git commit` 은 로컬에 남지만 `git push` 는 항상 실패합니다.
**커넥터의 GitHub API 호출만이 유일한 쓰기 경로입니다.**

### 실제 절차 — 다섯 단계

```
1. 세션 안에서 파일을 고칩니다
2. git hash-object <파일>          ← 목표 해시를 적어 둡니다
3. 커넥터 샌드박스에 저장소를 clone 하고, 같은 편집을 다시 실행합니다
4. 샌드박스에서도 git hash-object → 2번과 같은지 대조합니다
5. 같을 때만 GITHUB_COMMIT_MULTIPLE_FILES 로 커밋합니다
```

3번을 "replay(재실행)"라고 부릅니다. 파일 내용을 통째로 옮기는 대신
**같은 문자열 치환을 다시 돌리는 것**이라 전송량이 거의 없습니다.

### 4번을 빼지 마세요

**커넥터를 지나면서 글자가 바뀐 적이 있습니다.**
`"장면보다 김"` 이 `"장면보다 길"` 로 도착했는데 **오류는 나지 않았습니다.**
base64 조각을 보낼 때도 두 번 깨졌고, 해시가 달라서 잡았습니다.

그래서 커밋 뒤에 저장소 전체를 다시 대조하는 스크립트도 하나 둡니다
(이 저장소의 `scripts/check_remote.py`). 로컬 blob 해시와 원격 blob 해시를
파일마다 맞춰 보고 다르면 이름을 찍습니다.

### 바이너리는 못 보냅니다

커넥터의 커밋 도구는 **글자만** 받습니다. PNG·MP4 는 못 올립니다.
base64 로 바꿔도 몇 MB 는 현실적으로 불가능합니다.

**해결: 만드는 쪽을 GitHub Actions 러너로 옮깁니다.**
러너에는 렌더 환경(브라우저·폰트)이 이미 있고, `GITHUB_TOKEN` 에
`contents: write` 가 있으니 자기가 만든 것을 자기가 커밋할 수 있습니다.

```yaml
      - name: 산출물을 저장소에 되돌리기
        run: |
          set -euo pipefail
          git config user.name  "<봇 이름>"
          git config user.email "<메일>"
          git add -A "$CONTENT/images" "$CONTENT/publish"
          if git diff --cached --quiet; then
            echo "바뀐 것이 없습니다."
          else
            git commit -q -m "chore: $CONTENT 산출물 갱신 (자동)"
            git pull --rebase -q origin main || true
            git push -q origin HEAD:main
          fi
```

### 알아둘 것

- 커밋 **작성자는 커넥터를 연결한 사람**으로 찍힙니다. 세션 전용 계정이 따로 있는 게 아닙니다
- 끊으려면 claude.ai 커넥터에서 GitHub 연결 해제. 그러면 읽기·편집까지만 됩니다
- 러너의 푸시는 커넥터와 **별개**입니다. 그것까지 막으려면 위 단계를 워크플로에서 빼세요

## 2. 유튜브 자동 업로드

### 준비물 세 개

구글 클라우드 콘솔에서 프로젝트를 만들고 **YouTube Data API v3** 를 켠 뒤,
OAuth 클라이언트(데스크톱 앱)를 만들면 두 개가 나옵니다.

| 값 | 어디서 |
|---|---|
| `YT_CLIENT_ID` | OAuth 클라이언트 생성 화면 |
| `YT_CLIENT_SECRET` | 〃 |
| `YT_REFRESH_TOKEN` | **본인 컴퓨터에서** 한 번 발급 (아래) |

### 갱신 토큰은 본인 컴퓨터에서 받습니다

세션 안에서 받으면 안 됩니다. 짧은 스크립트를 하나 두고
(`scripts/yt_token.py` 참고) **사람이 자기 PC에서** 돌립니다.
브라우저로 동의하고 주소창의 `code=` 값을 붙여넣으면 갱신 토큰이 나옵니다.

> **토큰을 대화창에 붙여넣지 마세요.** 값은 GitHub Actions Secrets 에만 넣습니다.
> 이 프로젝트에서 지키는 규칙이고, 옮길 때도 그대로 가져가세요.

### 저장 위치

저장소 → Settings → Secrets and variables → Actions → New repository secret.
위 세 개를 그대로 넣습니다. 워크플로에서는 이렇게만 받습니다.

```yaml
env:
  YT_CLIENT_ID:     ${{ secrets.YT_CLIENT_ID }}
  YT_CLIENT_SECRET: ${{ secrets.YT_CLIENT_SECRET }}
  YT_REFRESH_TOKEN: ${{ secrets.YT_REFRESH_TOKEN }}
```

**빈 시크릿 함정** — 러너는 없는 시크릿을 **빈 문자열**로 넘깁니다.
`os.environ.get("YT_CLIENT_ID", "기본값")` 은 그때 기본값을 안 씁니다.
`os.environ.get(k) or "기본값"` 으로 받으세요.

### 올리는 방법

갱신 토큰 → 접근 토큰 → **재개 가능한 업로드**(자리 예약 후 파일 전송) 순서입니다.
표준 라이브러리 `urllib` 만으로 됩니다. 외부 패키지가 필요 없습니다.

기본값은 **미리보기**로 두고, `--publish` 를 붙여야 실제로 올라가게 하세요.
실수로 올라가는 것보다 한 번 더 누르는 편이 낫습니다.

### 제약 네 가지 — 미리 알고 시작하세요

| 제약 | 내용 |
|---|---|
| **앱 검수 전에는 비공개만** | 구글 검수를 안 받은 앱은 `private` 로만 올라갑니다. 올리는 것 자체는 됩니다 |
| **테스트 상태면 토큰이 7일마다 만료** | OAuth 동의 화면을 **'프로덕션'으로 게시**해야 안 끊깁니다. 이거 모르면 일주일 뒤에 갑자기 안 됩니다 |
| **쿼터** | 하루 10,000 units, 업로드 1건에 약 1,600 → **하루 6편**이 상한입니다 |
| **쇼츠 썸네일은 API 로 못 붙입니다** | 처음엔 유튜브가 아무 프레임이나 집습니다. 올린 뒤 유튜브 스튜디오(웹)에서 손으로 바꿀 수는 있습니다 |

마지막 것 때문에 이 프로젝트는 **모든 프레임이 썸네일이 되도록** 영상을 만듭니다 —
주제어를 전 프레임에 남기고, 0.00초 프레임을 완성 상태로 둡니다.
